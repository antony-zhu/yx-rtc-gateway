# 平台设计稿-评审修订版

> 本文件基于 `docs/design/平台设计稿.md` 评审整理，不覆盖原始草稿。当前版本重点对齐权限边界、项目前端层级、设备组配置、产品型号和固件版本管理。

## 1. 评审结论

整体方向可行：平台围绕“用户 - 项目 - 设备组 - 设备”管理网关，设备通过 MQTT 管理通道接入平台，用户在自己的项目和设备组内完成设备、配置、发布和同步操作。

需要明确并固化的关键口径：

- 平台管理员只做平台级管理，不替用户管理项目、设备组和配置。
- 未分配设备池仅平台管理员可见，且只用于展示、查看、停用、备注、导出等平台资产操作，不提供“选择并加入组”。
- 用户添加设备的入口在“项目详情 - 设备组详情”中，用户输入设备编号，后端校验该设备是否在未分配池；绑定不依赖设备是否在线。
- 设备组归属于项目。前端不应把“项目详情、设备组详情、设备组配置”放进左侧菜单，它们都是从项目管理逐级进入的页面状态。
- 设备组分为正式设备组和测试设备组。测试组配置可编辑、保存、复制并发布到关联正式组；测试组同时区分“草稿配置”和“正在测试配置”。正式组配置只可查看和复制，运行配置全组统一，但缓存最近 8 份历史快照供查看。
- 脚本和参数配置是一体的设备组配置版本。不存在“配置一个流水号、脚本一个流水号”的拆分口径。
- 产品型号和固件版本由平台管理员维护。新增产品型号时可以顺带新增固件版本；新增固件版本时必须声明适用产品型号，并携带该固件的配置能力清单。

## 2. 角色与权限

### 2.1 平台管理员

平台管理员管理平台级资源，不进入用户内部项目代替用户操作。

| 能力 | 说明 |
|---|---|
| 用户管理 | 创建、停用、编辑用户，创建用户管理员账号 |
| 设备管理 | 查看全平台设备，只展示设备归属到哪个用户，不展示用户内部项目和设备组 |
| 未分配设备池 | 查看未分配设备、预录入设备、停用设备、导出设备 |
| 产品型号管理 | 新增、编辑、停用产品型号，维护硬件产品身份和接入能力 |
| 固件版本管理 | 新增固件版本，声明适用产品型号，维护文件、版本号、校验信息和固件配置能力清单 |
| 平台审计 | 查看平台级操作、设备接入异常、用户管理记录 |

平台管理员不应直接执行：

- 为用户创建项目。
- 为用户创建设备组。
- 把未分配设备加入某个用户的设备组。
- 编辑用户设备组配置。
- 发布用户测试组配置到正式组。

### 2.2 用户管理员

用户管理员管理本用户下业务资源。

| 能力 | 说明 |
|---|---|
| 项目管理 | 创建、编辑、删除本用户项目 |
| 设备组管理 | 在项目下创建正式设备组或测试设备组 |
| 设备添加 | 在设备组详情中输入设备编号，后端校验设备是否在未分配池 |
| 设备管理 | 查看、编辑备注、转移、移出本用户设备 |
| 配置管理 | 编辑测试设备组配置，复制正式配置；从设备组列表发布测试配置到正式组 |
| 子用户管理 | 创建子用户，配置项目、设备组和动作权限 |
| 任务日志 | 查看本用户范围内同步任务、异常和审计 |

### 2.3 子用户

子用户只能访问用户管理员授权的项目、设备组和操作。

可配置权限示例：

- 只读查看。
- 设备添加/移除。
- 配置编辑。
- 配置发布。
- 远程同步。
- 日志查看。

## 3. 核心对象

| 对象 | 归属 | 说明 |
|---|---|---|
| 用户 | 平台 | 业务客户或租户 |
| 项目 | 用户 | 用户内部业务管理边界 |
| 设备组 | 项目 | 正式/测试设备组，绑定产品型号、固件版本和组配置版本 |
| 设备 | 用户/项目/设备组 | 设备必须归属到某个设备组，未绑定时位于未分配设备池 |
| 产品型号 | 平台 | 硬件/产品代号，由平台管理员维护，不承载配置能力清单 |
| 固件版本 | 平台 | 固件包及版本，由平台管理员维护，并声明适用产品型号、系统变量/函数、通道槽位、预置变量/函数和迁移规则 |
| 设备组配置 | 设备组 | 参数、数据流和脚本的一体化版本 |

## 4. 设备绑定与未分配池

### 4.1 未分配设备池

未分配设备池仅平台管理员可见，用作平台资产和接入状态展示。

设备进入未分配池的场景：

- 设备已通过 HTTP/MQTT 接入平台，但尚未绑定用户、项目和设备组。
- 平台管理员提前预录入设备编号。
- 用户将设备从设备组移出，或项目/设备组删除导致设备解绑。

未分配设备池页面字段建议：

| 字段 | 说明 |
|---|---|
| 设备编号 | deviceId |
| 产品型号 | 设备上报或预录入的产品型号 |
| 来源 | 上线注册、平台预录入、用户解绑 |
| 在线状态 | 在线、离线 |
| 固件版本 | 设备当前固件版本，预录入设备可为空 |
| 首次入池时间 | 进入未分配池时间 |
| 最后心跳时间 | 最近设备心跳 |
| 所属用户 | 未分配时为空 |
| 操作 | 查看详情、停用/启用、备注、导出 |

未分配设备池不提供“加入设备组”或“绑定到项目”操作。

### 4.2 用户添加设备

用户添加设备必须在设备组详情页完成。

流程：

1. 用户进入“项目 - 项目详情 - 设备组详情”。
2. 点击“添加设备”。
3. 输入设备编号。
4. 后端校验设备是否存在于未分配池。
5. 后端校验设备产品型号是否与当前设备组兼容。
6. 校验通过后，设备归属到当前用户、项目和设备组。
7. 在线设备立即同步归属和设备组配置；离线设备等待上线后同步。

错误提示建议：

- 设备编号不存在。
- 设备不在未分配池。
- 设备已被其他用户绑定。
- 设备产品型号与当前设备组不匹配。
- 当前用户无权向该设备组添加设备。

## 5. 项目与设备组

### 5.1 前端层级

左侧菜单只保留稳定功能入口。

用户端页面层级：

```text
项目
  └── 项目详情
      └── 设备组详情
          ├── 组内设备
          ├── 添加设备
          ├── 转移/移出设备
          └── 设备组配置
```

不应放入菜单的页面：

- 项目详情。
- 设备组详情。
- 设备组配置。
- 设备详情。

这些页面通过列表点击、面包屑和返回按钮进入。

### 5.2 设备组类型

设备组属于项目，并分为两类：

| 类型 | 说明 |
|---|---|
| 测试设备组 | 配置可编辑、可保存、可复制、可发布到关联正式组 |
| 正式设备组 | 配置不可直接编辑，只可查看和复制 |

命名规则建议：

- 同一项目下，同类型设备组不可重名。
- 测试组和正式组可以同名，但页面上必须清楚展示组类型。

设备组字段建议：

| 字段 | 说明 |
|---|---|
| 设备组名称 | 项目内展示名称 |
| 设备组类型 | 正式、测试 |
| 关联正式组 | 测试组发布时的目标正式组 |
| 产品型号 | 当前设备组允许接入的产品型号 |
| 固件版本 | 当前设备组目标固件版本 |
| 组配置版本 | 参数、数据流和脚本的一体版本号 |
| 设备数量 | 组内设备数量 |
| 未同步设备数量 | 当前设备版本与组目标不一致的设备数 |

### 5.3 设备组删除

删除设备组前应二次确认。

删除后：

- 设备组软删除。
- 组内设备移回未分配状态。
- 在线设备下发归属清空或新归属同步。
- 离线设备等待上线后同步。
- 历史配置、发布记录、任务和审计保留。

## 6. 设备组配置

### 6.1 版本口径

设备组配置是一个整体版本，包含：

- 基础参数。
- 网络通道参数。网络通道数量、类型和通道 ID 由固件版本配置能力清单声明，设备组只配置参数和启停，不新增/删除通道槽位。
- 硬件通道参数。UART、RS485、I2C、SPI 等硬件通道类型、通道 ID 和参数表归属于固件版本，设备组只配置参数，不新增硬件通道。
- 数据流配置。
- 脚本内容。
- 同步策略。

每次保存配置后生成或更新一个统一的配置版本号，例如 `组配置 V100`。参数和脚本共同参与 hash 计算。

测试组配置有两个状态：

- 草稿配置：用户编辑和保存的未同步版本。进入测试组配置页时，如果存在草稿，默认加载草稿。
- 正在测试配置：已经保存并同步到测试组设备的目标配置。若测试组没有草稿，进入配置页默认加载正在测试配置。

测试组可以删除草稿。删除草稿只移除未同步的编辑版本，不影响正在测试配置和测试组设备目标配置。

正式组运行配置必须全组统一，同一时刻只有一个正在运行的配置版本。正式组缓存最近 8 份配置快照，用于切换查看历史版本或复制为测试配置；切换查看历史不改变正式组正在运行的配置。

不采用以下拆分：

- 配置流水号。
- 脚本流水号。
- 配置版本和脚本版本分别同步。

### 6.2 编辑与发布

测试设备组：

- 可编辑配置。
- 可保存草稿。
- 可删除草稿；删除后配置页回到正在测试配置。
- 可复制配置。
- 可将草稿保存并同步为正在测试配置。
- 可将已经验证通过的正在测试配置发布到关联正式组。

正式设备组：

- 不可直接编辑配置。
- 可查看配置。
- 可切换查看最近 8 份历史配置快照。
- 可复制为测试组配置。
- 接收测试组发布后的配置版本，并将其作为全组唯一正在运行配置。

发布流程：

1. 从正式组复制配置到测试组，或直接编辑测试组配置。
2. 测试组保存草稿，形成草稿配置版本。
3. 保存并同步测试组，将草稿变为正在测试配置，并下发给测试组设备验证。
4. 验证通过后，从设备组列表发布正在测试配置到关联正式组。
5. 正式组配置版本更新为全组唯一正在运行配置，并把旧运行配置写入历史快照缓存。
6. 平台按同步策略向正式组设备下发。

### 6.3 配置依赖

配置依赖：

- 产品型号。
- 固件版本。
- 设备组。

产品型号用于约束设备和固件是否兼容；可编辑的配置模板主要由设备组绑定的固件版本决定。前端进入设备组配置页时，应根据固件版本加载系统变量、系统函数、固件预置自定义变量/函数、网络通道槽位、硬件通道类型和参数表。

### 6.4 变量引用规则

设备组配置中的以下内容都可以使用 `${变量名}` 语法引用变量：

- 配置参数，包括基础参数、网络通道参数、硬件通道参数、同步策略等可配置字段。
- 自定义变量的值。
- 自定义函数的默认值、函数说明和脚本内容。
- 数据流节点属性，例如通道 Topic、JSON Key、固定值、函数参数默认值等。

变量来源分为两类：

- 系统变量：变量名、类型和可用范围由固件配置能力清单声明；变量值由平台按设备、项目、设备组和运行上下文注入，例如 `${deviceId}`、`${projectId}`、`${groupId}`、`${productModel}`、`${firmwareVersion}`。
- 自定义变量：包括固件预置自定义变量，以及用户在当前设备组配置中增补维护的变量，例如 `${station_id}`、`${temperature_threshold}`、`${raw_prefix}`。

解析规则：

- 系统变量名为保留名，自定义变量不能覆盖系统变量。
- 固件预置自定义变量应有稳定 Key；固件升级时按 Key 做迁移，类型变化、删除或新增必填变量必须给出迁移提示。
- 变量在具体设备执行配置、脚本或数据流时按设备上下文解析。例如 `${deviceId}` 在不同设备上解析为各自的设备编号。
- 变量引用应保留原始类型。若变量出现在字符串模板中，则按字符串插值；若字段声明为 number、boolean、json、list、bytes，则后端应按目标类型校验和转换。
- 变量可以嵌套引用自定义变量，但必须禁止循环引用。
- 未定义变量、类型不匹配、循环引用应在保存或发布前提示，不应等到设备执行时报错。
- 若需要输入字面量 `${...}`，前端应提供转义方式或明确提示。

## 7. 产品型号与固件版本

### 7.1 产品型号添加

产品型号只能由平台管理员添加。

建议字段：

| 字段 | 说明 |
|---|---|
| 产品型号 | 例如 `DTU01A`、`DTU01B` |
| 产品名称 | 页面展示名 |
| 硬件类型 | 例如 4G DTU、以太网网关 |
| 硬件版本 | 硬件迭代标识 |
| 联网能力 | WiFi、4G、Ethernet |
| 注册凭据 | 设备接入平台所需产品级凭据 |
| MQTT 接入信息 | 产品级 MQTT 用户名、密码、接入策略 |
| 默认固件版本 | 可选 |
| 状态 | 启用、停用 |

新增产品型号时，可选同时新增一个固件版本。这样可以避免新增产品后还要切到固件页面重复录入。

产品型号只维护硬件产品身份、接入能力和固件适用关系，不维护系统变量、系统函数、网络通道槽位、硬件通道类型或设备组配置模板。

### 7.2 固件版本添加

固件版本只能由平台管理员添加。

新增固件版本必须声明适用产品型号。

建议字段：

| 字段 | 说明 |
|---|---|
| 固件版本号 | 例如 `1.0.0`、`1.2.3` |
| 适用产品型号 | 可选择一个或多个产品型号，按实际兼容策略确定 |
| 固件文件 | 上传固件包 |
| 文件大小 | 自动计算 |
| SHA256 | 自动计算或录入后校验 |
| 配置能力清单 | 固件声明的系统变量、系统函数、网络通道槽位、硬件通道类型、预置自定义变量和预置自定义函数 |
| 配置迁移规则 | 从上一固件版本迁移时的稳定 Key 映射、默认值、废弃项、类型变化说明 |
| 发布说明 | 变更说明 |
| 状态 | 草稿、可用、停用 |

前端固件管理建议拆成三层：

- 固件版本列表：展示固件版本、适用产品型号、状态、能力清单摘要、基于版本、迁移状态、SHA256、创建时间和操作入口；支持按版本、产品型号、状态和迁移状态筛选。
- 固件详情：用 tab 展示基础信息、配置能力清单、迁移规则、使用情况和审计记录；能力清单中分别展示系统变量、系统函数、固件预置函数、预置变量、网络通道槽位、硬件通道和参数表。
- 新增固件版本：采用弹窗或抽屉式向导，按“基础信息 -> 能力清单 -> 迁移规则 -> 校验发布”组织；推荐支持从同产品型号上一固件复制能力清单后编辑差异。

固件状态和可编辑性：

- 草稿固件可编辑能力清单和迁移规则。
- 可用固件的能力清单应只读；后续变更通过复制新增版本完成，避免已绑定设备组的配置语义漂移。
- 停用固件不再允许新设备组选择，但历史设备组和审计记录仍可查看。

关系口径：

- 固件版本依赖产品型号。
- 设备组选择产品型号后，只能选择适用于该产品型号的固件版本。
- 新增产品型号时可以顺带新增固件版本，但新增固件版本仍必须明确适用产品型号。
- 固件版本是配置能力清单的归属方。系统变量、系统函数、固件预置自定义变量/函数、网络通道数量和硬件通道类型都跟随固件版本。

### 7.3 固件配置迁移性

固件升级或设备组目标固件切换时，必须先对配置模板做迁移评估：

- 每个系统变量、系统函数、预置自定义变量/函数、网络通道槽位、硬件通道都必须有稳定 Key，例如 `deviceId`、`parse_modbus_float`、`net_mqtt`、`serial_com1`。
- 固件配置能力清单应声明类型、方向、参数表、默认值、是否必填、是否可废弃、替代 Key 和版本范围。
- 从旧固件迁移到新固件时，后端生成差异：保留、改名、类型变化、参数范围变化、删除、新增必填项、新增可选项。
- 保留项按稳定 Key 自动迁移；改名项必须由固件迁移规则显式声明；删除项若仍被配置、变量、函数或数据流引用，应阻止切换或要求用户处理。
- 新增必填变量、函数参数、通道参数或通道槽位必须给出默认值或要求用户补充，否则不能发布。
- 固件迁移只保证配置结构可迁移和可校验，不保证用户脚本或自定义函数的业务语义仍然正确，仍需要测试组验证后发布。

## 8. 页面设计建议

### 8.1 平台端菜单

```text
平台首页
```

### 8.4 设备组配置页

设备组配置页应突出“一体版本”：

- 顶部展示：项目、设备组、组类型、产品型号、固件版本、当前组配置版本、hash。
- Tab：基础参数、网络通道、硬件通道参数、数据流、脚本、同步策略、版本记录。
- 保存按钮：保存草稿。
- 测试组按钮：保存草稿、删除草稿、保存并同步测试组；发布不在配置页执行。
- 测试组加载规则：优先加载草稿；没有草稿时加载正在测试配置。页面必须同时展示草稿版本和正在测试版本，避免用户误以为保存草稿已经影响测试设备。
- 正式组按钮：查看历史版本、复制为测试配置。正式组页面可切换查看最近 8 份历史快照，但必须明显标识当前运行配置只有一个。
- 数据流约束：输出锚点可以流向多个输入锚点，用于一对多分发；输入锚点只能被一条线流入。通道节点在画布上拆分为“通道输入”和“通道输出”两类节点，同一通道同一方向最多创建一个；任意节点的上游动态输入源最多只能有一个。
- 数据流通道来源包括两类：固件版本定义的网络通道槽位，以及固件版本定义的硬件通道。二者都通过“通道输入 / 通道输出”节点表达，具体通道、动作和端口类型在节点属性中选择。
- 数据流节点分为固定锚点和可扩展锚点两类。通道输入/输出、值转 JSON、自定义函数等节点锚点数量固定；JSON 合并等聚合节点可在输入区通过紧凑的“+ / -”添加或删除未连线输入锚点。
- 数据流左侧模块库按通道、变量、内置函数、函数库组织；每个一级模块都使用可折叠面板，减少长列表占用空间。变量类型包括 string、number、boolean、json、list、bytes、any，内置函数再按类型转换、JSON、消息分层；函数库按系统函数、固件预置函数、用户自定义函数折叠分组；json 变量需要单独编辑字段 key、value 和字段类型，list 变量按 JSON 数组格式展示和编辑，bytes 变量按 `AA 55 66 77 88` 这种两位十六进制空格分隔格式展示和编辑。
- 自定义变量表的“值”列应靠近“类型”列，不让说明列前的空白把值推到页面中部；bytes/十六进制变量统一按 `AA 55` 这种两位一组、空格分隔格式展示和编辑，不使用 `0xAA55`。
- 配置、自定义变量、自定义函数、数据流都支持 `${变量名}` 语法引用系统变量和自定义变量，例如 `${deviceId}`。变量引用在设备执行上下文中解析，并参与配置保存、校验和发布流程。
- 数据流保存：节点位置必须随数据流配置一起保存和加载，避免节点较多时重新打开后布局错乱。
- 数据流快捷操作：支持 Ctrl+Z 撤销、Ctrl+Shift+Z/Ctrl+Y 重做、Ctrl+C/Ctrl+V 复制粘贴节点、Ctrl+D 快速复制、Delete/Backspace 删除选中对象。
- 数据流连线支持拖动重连。拖动已有连线时按起手位置判断重连源端或目标端；重连源端时允许选择已有出线的输出锚点，重连目标端时必须松到未被占用的输入锚点，松到空白或非法锚点时恢复原连线。
- 自定义函数不再手工维护输入输出表；用户只编辑函数注释和函数代码，前端/后端从 `@inputs`、`@outputs` 注释自动解析输入输出端口。入参必须声明必填或可空；可空参数允许在数据流中不连线，并应声明默认值或 None 处理。
- 函数展示模块名从 `@module` 注释解析，例如 `# @module: 状态归一化`；代码里的 Python `def` 函数名统一使用英文标识符，例如 `def status_normalize(status):`。如果缺少 `@module`，前端可回退显示英文函数名。
- 函数库页面按可折叠菜单组织：系统函数、固件预置函数、用户自定义函数都放在同一个函数库中展示；系统函数和固件预置函数由当前固件版本给出，只读展示，用户自定义函数保存在设备组配置中。左侧展示函数名称、语法状态、来源、引用情况和输入输出数量，右侧点开具体函数后才展示代码与自动解析出的输入输出；函数草稿可以保存未通过语法检查的内容，页面只提示状态，不判断业务功能是否正确。
- 自定义函数必须使用稳定 `functionId` 作为引用键；展示模块名从 `@module` 自动解析。用户修改模块名后，函数库列表、数据流左侧函数列表和画布中已引用该函数的节点显示名应同步更新；用户修改 `@inputs` / `@outputs` 后，画布中已引用该函数的节点端口和锚点也应同步更新，但数据流引用关系不应因为改名而断开。
- 数据流左侧“函数库”列表应展示全部可见函数，包括系统函数、固件预置函数、用户自定义函数，以及未通过语法检查的用户函数。未通过的函数在列表中标红，但仍允许放入数据流；保存并同步测试组时，如果数据流引用了未通过的函数，校验应报错并阻止同步。
- 网络通道也采用通道 tab + 表单配置，不使用密集表格；tab 标题使用面向用户的通道名称/用途加联网方式，例如“主上报通道 / MQTT”，通道 ID 作为后端和数据流引用的稳定键在表单内展示。网络通道数量和类型来自固件版本，设备组不新增/删除通道槽位。
- 网络通道和硬件通道的 tab 标题需要直接展示启用/停用状态，状态随表单里的“是否启用/是否启动”字段同步变化。
- 硬件通道参数采用硬件通道 tab + 表单配置，不使用密集表格；UART、RS485 等串口类硬件展示启用、波特率、数据位、校验位、停止位、打包超时时间等字段，下拉选项来自固件版本配置能力清单。

#### 数据流最新设计口径

- 左侧模块库分为：通道、变量、内置函数、函数库。
- 通道节点只提供“通道输入”和“通道输出”。可选通道来自当前固件版本配置能力清单；节点属性选择具体通道、动作、端口类型，MQTT 节点额外配置 Topic。
- 通道输入/输出节点的核心参数不再显示一条可编辑的 `channel=...` 值摘要；属性面板以结构化字段展示通道、动作、Topic/资源和数据类型，并在只读摘要中展示通道 ID。节点卡片展示用户可理解的通道名称、联网方式、动作、数据类型和 Topic。
- 变量节点按类型创建：string、number、boolean、json、list、bytes、any。
- json 变量不是整段文本输入，属性面板拆成字段 Key、字段值、字段类型，节点卡片展示为 `key: type = value`。
- list 变量按 JSON 数组格式输入和展示，例如 `["warn", "alarm"]`；数据流端口类型显示为 `list`，仅与 list 或 any 端口直接兼容。
- bytes 变量按两位十六进制一组、空格分隔、大写展示，例如 `AA 55 66 77 88`。
- 内置函数当前保留类型转换和 JSON 类能力：hex 转字符串、字符串转 hex、值转 JSON、JSON 提取、JSON 合并。消息组合和消息分发控件暂不放入左侧模块库。
- 节点卡片分为顶部信息、输入区、输出区三个视觉区块，中间用分隔线区分。
- 端口文本统一展示为 `端口名: 类型`。端口类型必须完整显示，不允许省略；端口名过长时允许省略。
- 必填输入不在节点卡片上标注；只有可选输入显示“选填”。
- 输入端口靠左，输出端口靠右；多输出节点需要支持输出名不等长时仍能清楚对齐。
- 连线方向为输出锚点流向输入锚点；输出锚点允许连出多条线，输入锚点最多只允许接收一条线。
- JSON 合并属于可扩展输入节点，输入区通过紧凑的“+ / -”添加或删除未连线输入锚点；语义是多个 JSON object 合并成一个 JSON object，不是数组打包。
- 右侧属性面板对多端口节点显示端口列表，列出方向、端口名、类型和连接状态，不再只展示输入数量或摘要卡片。
- 动态输入源指 UART/RS485 接收、MQTT 订阅、HTTP/WebSocket 接收等可独立触发数据流的通道输入。任意节点的全部上游链路中只能存在一个动态输入源，禁止两个动态输入源直接或间接汇入同一个节点；变量、常量、配置参数等静态输入可以与一个动态输入源组合使用。若后续确实需要多源汇聚，必须新增具备明确等待、窗口、缓存和冲突处理策略的专用汇聚节点。

## 10. 后端可实现性要求

前端原型应假设后端具备以下校验：

- 用户添加设备时，后端按设备编号校验设备是否在未分配池。
- 用户添加设备时，后端校验当前用户、项目、设备组权限。
- 用户添加设备时，后端校验设备产品型号与设备组产品型号兼容。
- 平台端未分配池接口只供平台管理员使用。
- 平台端设备列表不返回用户内部项目和设备组信息，或前端不展示这些字段。
- 设备组配置保存时，参数和脚本一起计算 hash，一起形成配置版本。
- 测试组配置保存草稿时，只更新草稿配置，不改变正在测试配置，不创建测试组设备同步任务。
- 测试组保存并同步时，后端先做完整同步校验；通过后将草稿配置提升为正在测试配置，并创建测试组设备同步任务。提升成功后可选择清空草稿或将草稿标记为已同步。
- 删除测试组草稿时，只删除草稿配置，必须保留正在测试配置。
- 正式组同一时刻只能有一个正在运行配置。测试组发布到正式组时，正式组当前运行配置被新版本替换，旧运行配置进入历史快照缓存。
- 正式组历史快照缓存最近 8 份配置；历史快照只读，可查看和复制为测试配置，不能作为正式组运行分叉。
- 正式设备组禁止直接编辑配置。
- 产品型号和固件版本写操作仅平台管理员可执行。
- 新增产品型号接口支持可选同步创建固件版本，或者前端在弹窗提交后按事务性流程调用产品型号与固件版本接口。
- 产品型号接口只返回产品身份、接入能力和可用固件关系；不要把系统变量、系统函数、网络通道槽位或硬件通道参数表放在产品型号上。
- 固件版本接口需要返回配置能力清单：系统变量、系统函数、固件预置自定义变量/函数、网络通道槽位、硬件通道类型、参数表、默认值和迁移规则。
- 固件版本列表接口应返回能力清单摘要、迁移状态、基于版本、SHA256、状态和使用统计；固件详情接口再返回完整能力清单、迁移差异、引用设备组和审计记录。
- 新增固件版本接口应支持从同产品型号已有固件复制能力清单，并在草稿状态下允许编辑能力差异；发布为可用前必须完成能力清单校验、迁移规则校验和文件校验。
- 设备组配置保存时，后端校验网络通道 ID、硬件通道 ID、系统变量、系统函数和固件预置项都必须来自当前固件版本配置能力清单，参数值必须在固件版本允许范围内。
- 硬件通道参数保存接口应按通道类型校验字段集合，例如 UART/RS485 校验波特率、数据位、校验位、停止位和打包超时时间，I2C/SPI 校验各自的速率、地址或模式等参数。
- 数据流保存接口应校验图结构：对每个节点追溯全部上游节点，若发现两个及以上动态输入源可到达同一节点，应拒绝保存并返回冲突路径；只有显式定义了等待、窗口、缓存和冲突处理语义的专用汇聚节点才允许例外。
- 网络通道保存接口应保存固件定义的 `channelId` 和面向用户展示的 `displayName`。`channelId` 由固件配置能力清单提供并保持稳定，供数据流引用；`displayName` 可编辑，用于页面 tab、列表和提示文案展示。
- 数据流通道节点保存时应使用结构化字段，例如 `nodeType`、`channelId`、`direction`、`action`、`dataType`、`topic/resource`，不要依赖前端展示用的拼接字符串反解析。
- 后端保存或发布设备组配置时，应扫描配置参数、自定义变量、自定义函数和数据流中的 `${变量名}` 引用，校验变量是否存在、是否存在循环引用、是否覆盖系统保留名，以及目标字段类型是否匹配。设备执行时按设备上下文解析系统变量，例如 `${deviceId}`。
- 自定义函数草稿保存接口应解析 `@module`、`@inputs` 和 `@outputs` 注释并返回语法状态，检查函数签名与注释一致、输入/输出数量上限、必填/可空/default 规则、类型枚举和 Python 语法；类型枚举至少包括 string、number、boolean、json、list、bytes、any、message。保存草稿不因语法未通过而失败，语法检查应使用 AST/解释器解析能力，不执行用户函数，也不承诺校验业务逻辑正确性。
- 函数库接口应返回稳定 `functionId`、函数来源（system/preset/user）、从 `@module` 解析出的展示模块名和英文 `def` 函数名。数据流节点保存时引用 `functionId`，不引用函数展示名；用户修改 `@module` 时只更新展示名，修改 `@inputs` / `@outputs` 时同步端口声明，不改变已有数据流节点的引用键；系统函数和固件预置函数由固件版本配置能力清单提供，只读不可改。
- 保存并同步测试组或发布前，后端必须校验当前数据流实际引用的自定义函数均已通过语法检查；未被数据流引用的错误函数可以继续作为草稿保留，不阻断同步。
- 固件版本切换或升级前，后端必须根据新旧固件配置能力清单生成迁移差异，并校验所有被配置、变量、函数、脚本和数据流引用的 Key 是否仍存在或存在显式迁移映射；存在无法迁移的删除项、类型不兼容项或缺少默认值的新增必填项时，应阻止保存或发布。

## 11. 待确认问题

- 产品型号是否全局唯一，还是允许不同平台租户复用相同编码。
- 一个固件版本是否允许适用多个产品型号，还是必须一对一绑定产品型号。
- 删除项目时，是禁止删除仍有设备的项目，还是允许删除并自动将设备移回未分配池。
- 子用户权限是否细化到设备组级别，还是只到项目级别。
