> **当前实现基线（2026-09-01）**：本文件包含早期脚本状态和预置 MQTT 失败分支。当前
> 嵌入式 C 固件生产仅使用统一 `dev_mqtt`，由 worker 通过 HTTPS 注册；MicroPython/用户

## 2. 分类原则

字段分为三类：

| 分类 | 用途 | 上报方式 |
| --- | --- | --- |
| 状态 | 描述设备当前运行态、任务态、在线态和故障态 | `up_raw` / `device.login.report`、`heartbeat.report`、`device.status.get` |
| 属性 | 描述设备身份、版本、参数、资源和配置 | `up_raw` / `property.report`、`property.get` |
| 诊断 | 描述最近错误、健康风险、日志内部状态和排障信息 | 可放入状态或属性，按字段归属决定 |

划分规则：

1. “现在正在做什么”放状态。
2. “设备是什么、配置是什么、资源是多少”放属性。
3. “最近一次失败为什么、内部队列是否满、故障摘要是什么”放诊断字段。
4. 密码、token、签名、MQTT 出厂密码、NVS 加密材料不得作为状态、属性或诊断明文上报。
5. UTC 不可信时，协议 `timestamp` 填 `0`，但 `uptime_ms` 或 `boot_uptime_sec` 仍应可用。

## 3. 通用报文字段

| 字段 | 类型 | 适用 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `version` | string | 所有协议报文 | 是 | 当前固定 `v1.0` |
| `method` | string | 所有协议报文 | 是 | 方法名或上报名 |
| `request_id` | string | 请求和应答 | 请求类必填 | 主动上报可省略或为空；建议不超过 64 字节 |
| `timestamp` | integer | 所有协议报文 | 是 | 毫秒 Unix 时间戳；UTC 不可信时填 `0` |
| `data` | object | 所有协议报文 | 按方法 | 业务数据 |
| `code` | integer | 应答 | 是 | 处理结果码，`0` 表示成功 |
| `message` | string | 应答 | 是 | 稳定英文短码 |

`request_id` 规则：

1. 请求方生成。
2. 设备保存最近 32 个平台下发的 `request_id`。
3. 运行中任务的 `request_id` 永远不能重复。
4. 已完成记录保留 1 小时。
5. 重复请求不重新执行，返回 `duplicate_request_id`。

## 5. 主状态枚举

| `status` | 说明 | 典型来源 |
| --- | --- | --- |
| `booting` | 设备启动中 | 启动阶段 |
| `offline` | 设备管理通道离线 | MQTT 未连接 |
| `online` | 设备管理通道在线 | `dev_mqtt` 已连接且订阅成功 |
| `config_checking` | 正在检查配置 | 配置检查流程 |
| `config_updating` | 正在更新配置 | `config.update` |
| `ota_checking` | 正在检查 OTA | OTA 检查流程 |
| `ota_upgrading` | 正在 OTA 升级 | `ota.upgrade` |
| `degraded` | 受限运行，仍保留设备管理能力 | `cfgfs` 异常、启动保护等 |
| `script_starting` | Python 脚本启动中 | `script_task` 启动 |
| `script_running` | Python 脚本运行中 | 脚本正常运行 |
| `script_stopped` | Python 脚本已停止 | 脚本未运行 |
| `script_error` | Python 脚本异常 | `SCRIPT_EXCEPTION` |
| `busy` | 设备正在执行互斥操作 | 非查询类任务 |
| `factory_resetting` | 正在恢复出厂 | `device.factory_reset` |
| `rebooting` | 即将重启或正在重启 | 受控重启流程 |

主状态选择建议：

1. OTA、配置更新、恢复出厂、重启优先于普通在线状态。
2. 如果设备管理通道在线但处于受限运行，可上报 `status=degraded`，同时 `mqtt_status=connected`。
3. 脚本状态不要覆盖设备管理状态；脚本状态放入 `script_status`。
4. 网络质量差不应把主状态改成 `degraded`，应使用 `network_status=degraded`。

## 6. 分状态枚举

### 6.1 network_status

| 值 | 说明 |
| --- | --- |
| `disconnected` | 网络未连接、未启动或当前不可用 |
| `connecting` | 正在联网 |
| `connected` | 网络已连接 |
| `degraded` | 网络已连接但质量差或不稳定 |

### 6.2 mqtt_status

| 值 | 说明 |
| --- | --- |
| `disconnected` | `dev_mqtt` 未连接 |
| `not_configured` | 出厂 MQTT 连接信息缺失或损坏 |
| `connecting` | `dev_mqtt` 正在连接 |
| `connected` | `dev_mqtt` 已连接 |
| `reconnecting` | `dev_mqtt` 正在重连 |
| `auth_failed` | `dev_mqtt` 鉴权失败 |

说明：

1. `mqtt_status` 只表示设备管理 MQTT。
2. 脚本 MQTT 失败不改变 `mqtt_status`。

### 6.3 script_status

| 值 | 说明 |
| --- | --- |
| `disabled` | 脚本被配置禁用 |
| `disabled_by_fault` | 因脚本异常重启风暴临时禁用 |
| `starting` | 脚本启动中 |
| `running` | 脚本运行中 |
| `stopped` | 脚本已停止 |
| `error` | 脚本异常 |

### 6.4 task_status

| 值 | 说明 |
| --- | --- |
| `idle` | 当前无设备管理任务 |
| `busy` | 正在执行普通互斥任务 |
| `config_checking` | 正在检查配置 |
| `config_updating` | 正在更新配置 |
| `ota_checking` | 正在检查 OTA |
| `ota_upgrading` | 正在 OTA 升级 |
| `log_uploading` | 正在上传日志 |
| `factory_resetting` | 正在恢复出厂 |
| `rebooting` | 正在重启 |

### 6.5 health_status

| 值 | 说明 |
| --- | --- |
| `ok` | 健康状态正常 |
| `warn` | 有资源风险或可恢复异常 |
| `degraded` | 局部能力已降级 |
| `fatal_pending` | 已发现系统级故障，等待或正在受控重启 |

| 408 | `timeout` | 请求、HTTP 或内部阶段超时 | 否 |

| 413 | `payload_too_large` | Payload 或查询结果过大 | 否 |

## 9. reason_code 字典

| reason_code | 推荐 code | 说明 | 兼容别名 |
| --- | ---: | --- | --- |
| `invalid_json` | 400 | JSON 非法 | `bad_json` |
| `missing_field` | 400 | 必填字段缺失 |  |
| `invalid_field` | 400 | 字段类型或取值非法 | `invalid_param` |
| `method_not_found` | 404 | 方法不支持 |  |
| `unsupported` | 501 | 协议已预留但当前固件未实现 |  |
| `payload_too_large` | 413 | MQTT Payload 超过 8192 字节 |  |
| `unauthorized` | 401 | 鉴权失败 |  |
| `not_found` | 404 | 资源不存在 |  |
| `http_connect_timeout` | 408 | HTTP/HTTPS 连接超时 |  |
| `http_response_interval_timeout` | 408 | HTTP/HTTPS 两次数据流间隔超时 |  |
| `dns_failed` | 408 | DNS 解析失败 |  |
| `time_not_trusted` | 409 | HTTPS、定时任务等操作需要可信 UTC，但当前 UTC 不可信 | `waiting_time_sync` |
| `tls_verify_failed` | 408 | HTTPS 证书链、域名或有效期校验失败 |  |

| `server_code_error` | 422 | HTTP POST 服务端 JSON `code != 200` |  |
| `device_busy` | 423 | 设备忙，非查询类指令被拒绝 |  |
| `log_upload_busy` | 423 | 日志 HTTP 上传任务已在运行 |  |
| `duplicate_request_id` | 425 | 重复 `request_id` |  |
| `version_not_increased` | 409 | 配置或 OTA 目标版本未递增 |  |
| `min_product_version_not_met` | 422 | 当前固件版本低于配置包要求 |  |
| `sha256_mismatch` | 422 | SHA-256 校验失败 |  |
| `size_mismatch` | 422 | 文件大小不匹配 |  |
| `invalid_manifest` | 422 | `manifest.jsonl` 格式或内容非法 |  |
| `path_traversal` | 422 | 路径规范化后越过允许目录 |  |
| `storage_full` | 507 | 存储空间不足 |  |

1. `message` 应使用稳定短码，推荐与 `reason_code` 保持一致。
2. 需要给人看的描述放入 `data.detail`，但必须脱敏。
3. `reason_code` 只描述最终失败原因；进度阶段另用 `stage` 或 `status`。
4. 同一请求最终应答只返回一个主要 `reason_code`，需要附加信息时使用 `data.detail`、`http_status`、`server_code`、`esp_err`。

## 10. HTTP 错误字段

凡是 MQTT 触发且需要 HTTP/HTTPS 的操作，最终失败应答应尽量携带：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `http_status` | integer | HTTP 状态码；未收到 HTTP 响应时填 `0` |
| `server_code` | integer | 服务端 JSON 中的 `code`；无 JSON 响应时可省略或填 `0` |
| `reason_code` | string | 本文档定义的失败原因 |
| `detail` | string | 脱敏后的失败摘要 |

填充规则：

| 场景 | `http_status` | `server_code` | `reason_code` |
| --- | ---: | ---: | --- |
| DNS 失败 | 0 | 0 或省略 | `dns_failed` |
| 连接超时 | 0 | 0 或省略 | `http_connect_timeout` |
| 应答间隔超时 | 0 | 0 或省略 | `http_response_interval_timeout` |
| HTTPS 发起前 UTC 不可信 | 0 | 0 或省略 | `time_not_trusted` |
| TLS 校验失败 | 0 | 0 或省略 | `tls_verify_failed` |
| TLS 握手或传输失败 | 0 | 0 或省略 | `tls_error` |
| HTTP 4xx | 实际状态码 | 0 或解析值 | `http_status_error` |
| HTTP 5xx | 实际状态码 | 0 或解析值 | `http_status_error` |
| HTTP 2xx 但 JSON `code != 200` | 实际状态码 | 实际 `code` | `server_code_error` |
| 下载大小不匹配 | 200 | 0 或省略 | `size_mismatch` |
| 下载 SHA-256 不匹配 | 200 | 0 或省略 | `sha256_mismatch` |
| 全部 HTTP 请求成功 | 200 | 200 或省略 | 不填或 `success` |

说明：

1. 多次 HTTP 请求的任务，失败时填导致最终失败的那次 HTTP 状态。
2. 配置更新下载多个文件时，某个文件失败就使用该文件对应的 HTTP 结果。
3. 日志 HTTP POST 上传以服务端 JSON `code=200` 作为成功。
4. 固件不执行 HTTP 注册；出厂 MQTT 信息缺失时只进入 `mqtt_status=not_configured`。

## 11. ESP-IDF 和系统错误字段

底层错误可在 `data` 中附加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `esp_err` | string 或 integer | ESP-IDF 错误码或名称 |
| `module` | string | 出错模块 |
| `stage` | string | 出错阶段 |
| `uptime_ms` | integer | 出错时本地运行时长 |

使用规则：

1. `esp_err` 用于辅助排查，不替代 `code` 和 `reason_code`。
2. ESP-IDF OTA 写入失败时，推荐 `reason_code=ota_write_failed`，并附加 `esp_err`。
3. `module` 和 `stage` 使用稳定英文短码。
4. 不得把敏感 URL、密码、token、密钥放入 `detail` 或 `esp_err` 上下文。

## 12. 敏感字段规则

禁止明文出现在状态、属性、日志、错误详情和诊断中的字段：

| 字段或内容 | 处理 |
| --- | --- |
| MQTT 密码 | 不上报、不打印 |
| MQTT 出厂 `password` | 不上报、不打印 |
| NVS 加密密钥和派生材料 | 不上报、不打印 |
| URL token、签名、密钥类 query | 脱敏或移除 query |
| Wi-Fi 密码 | 默认不上报；确需下发时应走受控配置 |
| 用户配置中的密钥类字段 | 脱敏 |

脱敏建议：

1. 标识符最多保留前 3 位和后 3 位，中间使用 `***`。
2. URL 默认只保留 scheme、host、path，不保留 query。
3. 证书、token、签名类错误只记录错误类型，不记录原始内容。

## 13. 实现要求

1. `gw_state` 负责聚合状态字段。
2. `property_manager` 或等价模块负责属性读写和敏感字段过滤。
3. `gw_protocol_manager` 负责统一生成 `code`、`message` 和 `reason_code`。
4. 所有 MQTT 上行发布前必须检查 Payload 不超过 8192 字节。
5. `property.get` 查询未知属性返回 `404 not_found`。
6. `property.set` 修改只读属性返回 `400 invalid_field`。
7. 非查询任务冲突返回 `423 device_busy`。
8. 重复 `request_id` 返回 `425 duplicate_request_id`。

## 14. 测试建议

1. 每个状态枚举都能被构造和上报。
2. `mqtt_status` 只受 `dev_mqtt` 影响，不受脚本 MQTT 影响。
3. `script_status=disabled_by_fault` 时，设备仍可上线和上报状态。
4. `property.get` 查询敏感字段不会返回明文。
5. `property.set` 修改只读字段被拒绝。
6. HTTP 连接超时、应答间隔超时、HTTP 4xx、HTTP 5xx、服务端 `code != 200` 均能填正确字段。
7. 配置包 SHA-256 错误返回 `sha256_mismatch`。
8. OTA 目标版本未递增返回 `version_not_increased`。
9. 日志大结果上传冲突返回 `log_upload_busy`。
10. UTC 不可信时所有协议 `timestamp` 为 `0`，但 `uptime_ms` 仍存在。
