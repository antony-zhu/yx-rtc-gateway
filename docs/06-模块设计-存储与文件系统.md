# 模块设计 - 存储与文件系统

## 1. 文档定位

本文档细化 `ESP32S3R8N16` 网关固件中的存储与文件系统模块，覆盖 NVS 系统参数、NVS 加密、LittleFS 三分区挂载、路径隔离、配置双区、用户数据区、日志区和异常降级策略。

本文档不重新定义 MQTT 协议字段、出厂 MQTT 连接信息、日志查询协议和 OTA 协议；这些内容以对应协议文档为准。

## 2. 设计目标

1. 系统参数统一保存在 NVS，并按约定加密。
2. 配置、用户数据、日志使用独立 LittleFS 分区，故障互不扩散。
3. `cfgfs` 负责配置双区，支持断电安全的整包更新。
4. `datafs` 只供脚本读写，写满或损坏不得影响设备管理平面。
5. `logfs` 只保存运行日志，写满后由后台任务清理，不阻塞主流程和脚本。
6. 所有路径在使用前必须规范化，允许出现 `../`，但最终路径不得逃出所属分区。
7. 启动时能区分核心存储故障和非核心存储故障，给设备状态上报提供明确原因。

## 3. 模块边界

建议目录：

```text
main/
  storage/
    gw_storage.c
    gw_nvs_store.c
    gw_storage_crypto.c
    gw_file_store.c
  fs/
    gw_fs.c
```

建议职责拆分：

| 子模块 | 主要职责 |
| --- | --- |
| `storage_core` | 存储模块初始化、状态汇总、故障摘要 |
| `nvs_store` | NVS namespace/key 读写、主副本、CRC、默认值 |
| `storage_crypto` | NVS 系统参数加解密、密钥派生、明文校验 |
| `fs_mount` | `cfgfs`、`datafs`、`logfs` 挂载和容量查询 |
| `fs_path` | 分区路径解析、脚本路径映射、目录穿透检查 |
| `file_store` | 临时文件、原子替换、文件 SHA-256、大小校验 |
| `cfg_slot` | 配置双区扫描、校验、生效区切换辅助能力 |
| `datafs_guard` | 用户数据区限额检查和写失败原因转换 |
| `logfs_guard` | 日志区容量统计、清理触发条件、索引文件辅助 |

不负责：

1. 不解析 MQTT 下行方法。
2. 不执行 HTTP 下载。
3. 不决定是否 OTA。
4. 不运行 Python 脚本。
5. 不主动清理 `datafs` 用户文件。
6. 不在调用线程中扫描或清理大量日志文件。

## 4. 固定分区

设备固定使用 16 MB Flash，分区如下：

| 分区 | 类型 | Offset | Size | 用途 |
| --- | --- | ---: | ---: | --- |
| `nvs` | data/nvs | `0x9000` | `0x20000` | 系统参数、运行参数、出厂 MQTT 信息、OTA 状态 |
| `otadata` | data/ota | `0x29000` | `0x2000` | ESP-IDF OTA 数据 |
| `phy_init` | data/phy | `0x2B000` | `0x1000` | PHY 初始化数据 |
| `factory` | app/factory | `0x30000` | `0x300000` | 出厂应用 |
| `ota_0` | app/ota_0 | `0x330000` | `0x300000` | OTA 应用分区 0 |
| `ota_1` | app/ota_1 | `0x630000` | `0x300000` | OTA 应用分区 1 |
| `cfgfs` | data/littlefs | `0x930000` | `0x400000` | 配置双区 |
| `datafs` | data/littlefs | `0xD30000` | `0x140000` | 用户脚本数据 |
| `logfs` | data/littlefs | `0xE70000` | `0x180000` | 运行日志 |

分区规则：

1. `cfgfs`、`datafs`、`logfs` 均使用 LittleFS。
2. `datafs` 和 `logfs` 直接使用分区根目录，不再创建固定 `/data` 或 `/log` 子目录。
3. `cfgfs` 是核心分区；配置双区均不可用时，设备进入受限运行。
4. `datafs` 和 `logfs` 是非核心分区；挂载失败、写满或损坏不得导致系统崩溃。
5. OTA 固件包不长期保存到 `cfgfs`、`datafs` 或 `logfs`。

## 5. 路径模型

文档、日志和内部诊断统一使用分区限定路径：

```text
cfgfs:/cfg_a/manifest.jsonl
cfgfs:/cfg_a/config.json
cfgfs:/cfg_a/main.py
cfgfs:/cfg_b/manifest.jsonl
cfgfs:/cfg_b/config.json
cfgfs:/cfg_b/main.py
datafs:/
logfs:/log_000001.jsonl
logfs:/index.json
```

脚本侧路径映射：

| 脚本访问路径 | 实际路径 |
| --- | --- |
| `/a` | `datafs:/a` |
| `/dir/file.txt` | `datafs:/dir/file.txt` |
| `/dir/../a` | `datafs:/a` |
| `/../../cfg_a/main.py` | 拒绝，路径逃出 `datafs:/` |

路径规范化规则：

1. 输入路径必须按 UTF-8 字符串处理。
2. 连续 `/` 视为一个路径分隔符。
3. `.` 路径段忽略。
4. `..` 路径段允许出现，但规范化后的路径深度不得小于分区根目录。
5. 规范化后不得生成空文件名、控制字符文件名或超过 LittleFS 限制的路径。
6. 脚本 API 不接受 `cfgfs:/`、`logfs:/`、Windows 盘符、反斜杠路径作为用户文件路径。

## 6. NVS 参数设计

### 6.1 参数分类

NVS 只保存设备系统参数和运行状态，不保存用户脚本业务数据。

| Namespace | Key 示例 | 是否加密 | 说明 |
| --- | --- | --- | --- |
| `factory` | `product_id`、`group_id`、`device_id`、`hw_model` | 是 | 出厂和设备身份参数；`device_id` 固定为硬件 MAC |
| `ble` | `alias`、`create_txn` | 是 | BLE 共享名称和最近一次新建任务的幂等恢复记录 |
| `mqtt` | `host`、`port`、`username`、`password`、`client_id`、`tls` | 是 | 出厂/维护流程写入的 MQTT 连接信息 |
| `system` | `hb_en`、`hb_sec`、`http_timeout`、`mqtt_reconnect_sec` | 是 | 可配置运行参数 |
| `config` | `active_slot`、`seq_id`、`manifest_sha256` | 是 | 当前生效配置区状态 |
| `ota` | `state`、`target_version`、`image_sha256`、`progress` | 是 | OTA 中间状态和恢复信息 |
| `time` | `last_trusted_utc` | 是 | 最近可信 UTC，毫秒 Unix 时间戳 |
| `stats` | `boot_count`、`last_reset_reason`、`fault_task` | 是 | 运行统计和最近故障摘要 |

说明：

1. 硬件 MAC 从芯片读取，NVS 可保存缓存副本或展示字段，但不得以 NVS 中的 MAC 覆盖硬件 MAC。
2. `product_id` 当前默认 `yx_gw`，出厂时应写入 NVS。
3. `group_id` 当前联调阶段暂时使用 `yx_gw`，用于设备管理 MQTT Topic 根路径，出厂时应写入 NVS。
4. `device_id` 固定等于硬件 MAC 十六进制大写字符串，不允许修改；升级时发现旧版 `MAC+01` 或自定义值会自动迁移回 raw MAC。
5. 用户自己的参数保存在当前配置区 `config.json` 或 `datafs:/`，不写入系统 NVS。
6. 所有通过 `gw_storage_secure_*` 保存的系统参数都会额外写入 `<key>_bak` 备份 key；ESP-IDF NVS key 最长 15 字节，因此这类内部 key 最长只能使用 11 个 ASCII 字符。新增 key 必须放在 `gw_param.h` 中，并通过编译期长度检查。

### 6.2 加密规则

NVS 系统参数使用确定性 AES 加密，目标是避免 Flash 或 NVS 直接读出明文。

固定算法：

1. MAC 使用硬件 MAC 的大写十六进制字符串。
2. 主密钥派生：`master_key = SHA256("yx_gateway_nvs_aes_v1:" + mac_upper)`。
3. 字段密钥派生：`field_key = SHA256(master_key + ":" + namespace + ":" + key_name)`。
4. 加密算法固定为 `AES-256-CTR`。
5. CTR 初值为 `SHA256("yx_gateway_nvs_ctr_v1:" + mac_upper + ":" + namespace + ":" + key_name)` 的前 16 字节。
6. 不使用随机 IV。
7. 加密前明文包必须包含魔数、版本、明文长度、CRC32 和副本代际 `generation`。
8. 解密后魔数、版本、长度或 CRC32 校验失败时，认为字段损坏。

建议明文包结构：

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| `magic` | 4 | 固定 `YXS1` |
| `version` | 1 | 当前写入 `2`；读取兼容旧版 `1` |
| `type` | 1 | 数据类型，例如 string、u32、u64、json、blob |
| `reserved` | 2 | 预留，填 0 |
| `plain_len` | 4 | payload 明文长度 |
| `crc32` | 4 | payload CRC32 |
| `generation` | 8 | V2 单调递增副本代际；V1 读取时按 0 处理 |
| `payload` | N | 原始数据 |

实现要求：

1. NVS 中保存密文 blob，不保存明文副本。
2. 加密材料不得写入日志、控制台和 MQTT 属性。
3. 解密失败必须返回明确错误，不得静默使用空值，除非该字段有明确默认值。
4. AES-CTR 加密只用于 NVS 系统参数，不用于用户脚本文件、运行日志和配置包内容。
5. 该方案不用于对抗已完全掌握设备和固件的强物理破解。

### 6.3 主副本和默认值

关键字段应使用主副本和备份副本：

| 字段 | 主 Key | 备 Key |
| --- | --- | --- |
| `device_id` | `factory.device_id` | `factory.device_id_bak` |
| MQTT 信息 | `mqtt.conn` | `mqtt.conn_bak` |
| 当前配置区 | `config.active` | `config.active_bak` |
| `last_trusted_utc` | `time.last_trusted_utc` | `time.last_trusted_utc_bak` |
| OTA 状态 | `ota.state` | `ota.state_bak` |

读取规则：

1. 同时读取并校验主 Key、备 Key。
2. 两份都有效时选择 `generation` 较大的副本，不能固定优先主 Key。
3. V1 两份记录的 `generation` 都视为 0；相同时优先备 Key，以恢复旧格式“备份已提交、主记录尚未提交”的掉电窗口。
4. 只有某个副本明确缺失或校验失败时才降级使用另一份；NVS I/O、内存不足等瞬时错误直接向上传递，不能返回可能过期的数据。
5. 主备都无效时，按字段默认值或异常策略处理；下一次成功写入会同步两个 V2 副本。

写入规则：

1. 在一次存储互斥事务中读取主备最大 `generation`，分配 `max + 1`。
2. 使用同一新 `generation` 先写备 Key，确认成功后写主 Key。
3. 若写完备 Key、写主 Key 前掉电，下一次读取仍会选中较新的备份，不回退旧主记录。
4. 任一步失败都返回 NVS 错误；写入成功后可读回校验关键字段。
5. V1 记录保持只读兼容，任意一次后续写入会自然迁移为 V2。

默认值规则：

| 参数 | 默认值 |
| --- | --- |
| `product_id` | `yx_gw` |
| `group_id` | `yx_gw` |
| `device_id` | 硬件 MAC 大写十六进制字符串 |
| 默认联网方式 | `4g` |
| APN | 空字符串 |
| HTTP 连接超时 | 10 秒 |
| HTTP 应答间隔超时 | 3 秒 |
| MQTT QoS | 1 |
| MQTT clean_session | 1 |
| MQTT retain | 0 |
| MQTT Last Will | 不启用 |
| MQTT 离线缓存 | 不启用 |
| 心跳周期 | 60 秒 |
| 日志保留目标 | 30 天 |
| 日志容量目标 | 1 MB |
| 日志扫描周期 | 1 天 |

## 7. LittleFS 挂载流程

启动挂载顺序：

1. 初始化 Flash 和 NVS。
2. 初始化 NVS 加密能力。
3. 读取或生成 `product_id`、`group_id`、`device_id` 基础参数。
4. 挂载 `cfgfs`。
5. 挂载 `datafs`。
6. 挂载 `logfs`。
7. 汇总文件系统状态，供状态上报和后续模块查询。

挂载策略：

| 分区 | 挂载失败策略 |
| --- | --- |
| `cfgfs` | 首次挂载失败后重试 3 次；仍失败则格式化并重新挂载一次；仍失败才标记配置不可用 |
| `datafs` | 首次挂载失败后重试 3 次；仍失败则格式化并重新挂载一次；仍失败才标记用户数据不可用 |
| `logfs` | 首次挂载失败后重试 3 次；仍失败则格式化并重新挂载一次；仍失败才降级本地日志 |

格式化策略：

1. 正常运行启动时，`cfgfs`、`datafs`、`logfs` 首次挂载失败后再重试 3 次。
2. 正常运行启动重试后仍失败，设备格式化对应分区并重新挂载一次。
3. 格式化后仍无法挂载，设备记录分区故障并按分区降级策略继续运行，不得循环格式化。
4. 出厂流程允许通过维护/产测入口显式格式化 `cfgfs`、`datafs`、`logfs`，可任意清空和重建分区。
5. 远程恢复出厂可以清空并重建 `cfgfs`、`datafs`、`logfs`。
6. 若后续需要支持远程单独格式化，必须作为显式维护接口，并通过 MQTT 返回结果。

## 8. cfgfs 配置双区

目录结构：

```text
cfgfs:/
  cfg_a/
    manifest.jsonl
    config.json
    main.py
  cfg_b/
    manifest.jsonl
    config.json
    main.py
```

双区规则：

1. `cfg_a` 和 `cfg_b` 一次只有一个当前生效。
2. 当前生效区、`seq_id` 和 `manifest_sha256` 保存在 NVS。
3. 配置包固定为 `manifest.jsonl`、`config.json`、`main.py` 和 `manifest.jsonl` 描述的其他文件整体。
4. 不支持单文件局部更新。
5. `seq_id` 只允许递增。
6. 两个区都有效且 `seq_id` 相同，默认选择 `cfgfs:/cfg_a`。
7. 两个区都无效时，视为无本地配置。
8. 单个配置区最大使用量为 1.8 MB。

配置区校验：

1. `manifest.jsonl` 能按 JSON Lines 解析。
2. `desc` 行存在且字段合法。
3. 必须包含 `config.json` 和 `main.py`。
4. 文件数量与 `file_count` 一致。
5. 每个文件大小与 SHA-256 一致。
6. 文件路径规范化后不得逃出当前配置区。
7. `min_product_version` 不高于当前固件版本。

断电安全更新流程：

1. 判断当前生效区。
2. 选择非生效区作为目标区。
3. 清理目标区临时文件和旧文件。
4. 下载新的 `manifest.jsonl.tmp`。
5. 校验 `manifest.jsonl.tmp` 的大小和 SHA-256。
6. 根据 manifest 下载全部文件到 `*.tmp`。
7. 校验每个临时文件大小和 SHA-256。
8. 原子替换目标区正式文件。
9. 完整校验目标区。
10. 写入 NVS `config.active_bak`。
11. 写入 NVS `config.active`。
12. 上报成功并重启。

失败策略：

| 失败点 | 处理 |
| --- | --- |
| manifest 下载失败 | 保留旧配置，上报失败 |
| manifest 解析失败 | 删除目标区临时文件，上报失败 |
| 文件下载失败 | 删除目标区临时文件，上报失败 |
| 文件校验失败 | 删除目标区临时文件，上报失败 |
| 目标区完整校验失败 | 不切换生效区，上报失败 |
| NVS 生效区写入失败 | 保留旧配置，上报失败 |

## 9. datafs 用户数据区

`datafs` 只供用户脚本读写，直接使用分区根目录。

固定规则：

1. 默认用户数据限额为 1 MB。
2. 限额为逻辑限额，不等于整个 `datafs` 分区物理大小。
3. 脚本写入前应通过快速统计或缓存计数判断是否可能超过限额。
4. 写入失败时返回明确错误给脚本。
5. 不自动删除用户文件。
6. 不因为 `datafs` 写满重启设备。
7. 配置更新和 OTA 不清空 `datafs`。
8. 远程恢复出厂会清空 `datafs`，但保留 `device_id`。

建议错误码：

| 场景 | 脚本错误 |
| --- | --- |
| 路径逃出 `datafs:/` | `EACCES` |
| 剩余额度不足 | `ENOSPC` |
| 文件系统未挂载 | `ENODEV` |
| 文件名非法 | `EINVAL` |
| LittleFS 写失败 | `EIO` |

容量统计策略：

1. 开机挂载 `datafs` 后扫描一次，得到初始使用量。
2. 脚本通过设备文件 API 写入、删除、截断文件时，更新内存计数。
3. 若检测到计数异常，可后台重新扫描校正。
4. 不在每次写入前扫描整个 `datafs`。

## 10. logfs 日志区

`logfs` 只保存设备运行日志、脚本异常日志和 MQTT 详细日志。

目录结构：

```text
logfs:/
  index.json
  log_000001.jsonl
  log_000002.jsonl
```

固定规则：

1. 日志写入由 `log_task` 完成。
2. 线程 1 和线程 2 只投递日志，不直接写 `logfs`。
3. 日志段文件固定 128 KB。
4. 单条日志最大 4096 字节。
5. 本地日志容量目标默认 1 MB。
6. 本地日志保留时间目标默认 30 天。
7. 日志扫描周期默认 1 天。
8. `logfs` 使用率超过 80% 或写入空间不足时触发后台清理。
9. 清理目标为 `logfs` 使用率不高于 50%。
10. 日志 MQTT 直传完整 Payload 最大 8192 字节，超过必须 HTTP POST。

写满保护：

1. 日志写入发现空间不足时，丢弃当前低优先级日志并触发 `log_clean_async()`。
2. 清理任务按最旧段文件优先删除。
3. 清理期间不阻塞线程 1 和线程 2。
4. 清理失败时暂停持久化日志，保留内存丢弃计数和最近错误摘要。
5. 日志恢复写入前应重新检查 `logfs` 状态。

索引策略：

1. `logfs:/index.json` 用于加速查询，不作为唯一可信数据。
2. 开机后 `log_task` 扫描 `log_*.jsonl` 重建或校正索引。
3. 索引损坏时删除索引并后台重建。
4. 日志查询对服务器隐藏段文件概念，只按条数、时间、等级和模块返回结果。

## 11. 文件写入原子性

对关键文件使用临时文件和原子替换：

```text
目标文件: cfgfs:/cfg_b/main.py
临时文件: cfgfs:/cfg_b/.main.py.tmp
```

写入流程：

1. 创建临时文件。
2. 分块写入并累计 SHA-256。
3. `fsync` 或 LittleFS 可用的同步接口。
4. 校验大小和 SHA-256。
5. 删除旧正式文件或重命名为备份。
6. 将临时文件重命名为正式文件。
7. 再次读取文件元信息确认。

适用范围：

1. 配置包文件。
2. `manifest.jsonl`。
3. `logfs:/index.json`。
4. 需要断电保护的系统状态文件。

不适用范围：

1. 普通运行日志追加。
2. 用户脚本自行写入的业务文件。

## 14. 恢复出厂

远程恢复出厂必须保留：

1. 硬件 MAC。
2. 由硬件 MAC 重新推导的固定 `device_id`。
3. `product_id`。
4. `group_id`。
5. 出厂必要参数。

远程恢复出厂必须清除：

1. MQTT 连接信息。
2. 心跳、授时、HTTP 超时、MQTT 重连等运行参数。
3. `cfgfs` 配置双区内容。
4. `datafs` 用户数据。
5. `logfs` 运行日志。
6. OTA 临时状态。
7. 运行统计。
8. `last_trusted_utc`。

恢复出厂流程：

1. 校验平台指令中的 `confirm=true` 和 `reason`。
2. 停止脚本。
3. 停止正在运行的配置、OTA、日志上传任务。
4. 清除 NVS 中可运行时重建的数据。
5. 清空并重建 `cfgfs`、`datafs`、`logfs`。
6. 写回保留字段。
7. 通过 MQTT 应答结果。
8. 重启设备。

## 15. 异常策略

| 异常 | 处理 |
| --- | --- |
| NVS 初始化失败 | 失败关闭；尽量上报故障；`NO_FREE_PAGES` 或 `NEW_VERSION_FOUND` 也不得在正常启动中自动擦除整区，只能由显式维护/恢复出厂流程处理 |
| NVS 字段解密失败 | 校验主备并选择最新有效副本；可选 BLE alias 主备都损坏时降级为空并尽力自愈 |
| NVS 主备都失败 | 使用默认值或进入对应降级状态 |
| `cfgfs` 挂载失败 | 重试 3 次后格式化并重新挂载；仍失败则配置不可用，等待配置修复 |
| `cfgfs` 双区都无效 | 无本地配置，线程 1 保持注册和 MQTT 能力 |
| `datafs` 挂载失败 | 重试 3 次后格式化并重新挂载；仍失败则脚本文件 API 返回失败，不影响线程 1 |
| `datafs` 写满 | 脚本写入失败，不自动删除用户文件 |
| `logfs` 挂载失败 | 重试 3 次后格式化并重新挂载；仍失败则关闭持久化日志，保留内存计数 |
| `logfs` 写满 | `log_task` 异步清理到 50% 以下 |
| `logfs` 清理失败 | 暂停持久化日志，不影响其他模块 |
| 路径穿透 | 拒绝访问并记录安全日志 |

## 16. 实现顺序

1. 完成 `storage_init()`、NVS 加密读写、默认值加载。
2. 完成三块 LittleFS 挂载和容量查询。
3. 完成路径规范化和 `datafs` 脚本路径映射。
4. 完成配置双区扫描和校验。
5. 完成 `datafs` 限额统计。
6. 完成 `logfs` 使用率统计和清理触发接口。
7. 完成恢复出厂流程。
8. 接入属性上报和状态上报。
